這裡會分別測試：① Apps Script 是否已部署 V6，② 寫入請求是否送達，③ 試算表是否真的出現這筆資料。測試寫入使用虛構內容且不公開。

檢查讀取與部署版本

不會新增任何使用者反思。

尚未測試。
02

實際寫入一筆不公開測試

和體驗者送出反思使用同一條寫入流程。

尚未測試。
03

再次核對剛才的寫入

使用唯一 ID 查驗，而不是看到「請求已發送」就當作成功。

先進行步驟 02。

怎麼判讀結果？

第一步失敗：通常是部署網址、存取權限或尚未更新 V6。請更新 Apps Script 的 Code.gs，再由「部署 → 管理部署作業 → 編輯 → 新增版本」發布，保留原網址。

第一步成功，第二步失敗：請先到 Google 試算表確認是否有 DeliveryLog 工作表；有 RECEIVED / ERROR 表示請求到達但後端寫入失敗；完全沒有紀錄，可能是 POST 根本沒送達，或網站連到錯誤部署。

第二步成功：會在 Responses 或 Responses_V3 增加一筆「系統連線測試」且狀態為 PRIVATE 的資料。此筆測試不會出現在交流牆，可以在確認後由主持教師手動刪除。

若是 Apps Script 編輯器中仍無法寫入，請直接執行 testWriteFromEditor。它會在執行紀錄中顯示寫入的工作表名稱與 ID。
